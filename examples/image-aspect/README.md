# Image element: size, position and alignment

Real renders produced by this working copy of CairoSVG, from local inputs only
(no network resource). Regenerate everything with:

```bash
export DYLD_FALLBACK_LIBRARY_PATH="/opt/homebrew/lib"   # or your Cairo path
.venv/bin/python examples/image-aspect/build.py
```

## Inputs

- `thumbnail.png`, generated by `build.py`: a 64×32 RGBA image with a
  two-pixel **fully transparent border**, four opaque colour quadrants
  (red/green top, blue/yellow bottom) and a **magenta centre square**.
  The transparent border makes it obvious whether alpha is really composited
  or silently filled with black; the quadrants and the centre square make the
  scale and the crop readable at a glance.
- `oriented.jpg`, generated by `build.py`: a 64×32 JPEG (red left, blue right)
  stored with **Exif orientation 6** (rotate 90° clockwise). Its displayed
  size is 32×64 with red on top.

## What each case shows

| File | Viewport | `preserveAspectRatio` | Result |
| --- | --- | --- | --- |
| `landscape-meet.png` | 220×140 | `xMidYMid meet` | Content 220×110, centred vertically; the bands above and below stay transparent (11.5 % blue overlay shows through). |
| `landscape-slice.png` | 220×140 | `xMidYMid slice` | Content 280×140; both sides are cropped to the viewport, centres preserved. |
| `landscape-none.png` | 220×140 | `none` | Content stretched to 220×140 on both axes independently. |
| `portrait-meet.png` | 100×200 | `xMidYMid meet` | Content 100×50, centred vertically. |
| `portrait-slice.png` | 100×200 | `xMidYMid slice` | Content 400×200; a narrow centre strip is visible, cropped on both sides. |
| `portrait-none.png` | 100×200 | `none` | Content stretched to 100×200. |
| `align-min.png` | 140×140 | `xMinYMin slice` | Content 280×140, the **left** edge is kept and the right half cropped. |
| `align-max.png` | 140×140 | `xMaxYMax slice` | Content 280×140, the **right** edge is kept and the left half cropped. |
| `auto-size.png` | width 200, height auto | `xMidYMid meet` | The missing height is deduced from the 2:1 intrinsic ratio (200×100), not from the file's pixel count. |
| `rotated.png` | `g` with rotate(30) + scale(1.4) | `xMidYMid slice` | The crop is computed in the image's own user space and then rotated with the container; nothing is cropped along the rotated axes by mistake. |
| `exif.png` | 100×200 | `xMidYMid meet` | The Exif orientation is applied first: the displayed image is 32×64 (portrait, red on top), so it fits the viewport without distortion. Ignoring the orientation would show a landscape 64×32 with red on the left. |

`overview.png` is a 3×2 contact sheet of the six main cases.

## Behaviour covered

- Intrinsic size, viewport size and alignment are computed independently:
  a missing `width`/`height` follows the intrinsic ratio, while an explicit
  value (including `0`) always wins; `preserveAspectRatio` (`meet`, `slice`,
  `none`, `xMin`/`xMid`/`xMax`, `YMin`/`YMid`/`YMax`, `defer`) only decides
  where the scaled content sits.
- The viewport is the clip region: neither a `slice` overflow nor the
  sampling halo of a stretched image paints outside its own box.
- Alpha coming from a channel, a palette `tRNS` entry or an RGB colour key is
  composited for real; transparent pixels never become opaque black.
- Exif orientation is applied before measuring, so the intrinsic size is the
  displayed pixel size.
- Embedded SVG documents use their own `width`/`height`/`viewBox` (including a
  non-zero origin) and their own `preserveAspectRatio`.
- Each reference is independent: the same file can be drawn at several sizes
  in one document, and repeated conversions are stable.
