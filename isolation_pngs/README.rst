Render-state isolation comparison images
========================================

Generated by ``generate.py`` (run from the repository root with the
project virtualenv). These images back the regression tests in
``cairosvg/test_state_isolation.py``; they are real renders, not mocks.

Pixel-identical pairs (must stay identical)
-------------------------------------------

* ``reference_baseline.png`` — baseline: four green squares, no effects.
* ``scenario_empty_layer.png`` — an empty layer carrying transform +
  clip-path + opacity group inserted before the same squares. Empty
  layers must begin and end cleanly at their call boundary.
* ``scenario_after_failed_layer_reused_entry.png`` — a layer with
  clip-path + transform + opacity group fails halfway (corrupt raster
  asset); the remaining layers and the *next image* are drawn through
  the same reused drawing entry. The failure must not leak transform,
  clip, operator, source or the transparency group to siblings or to
  the next image.

Shared paint-server definitions
-------------------------------

* ``pattern_siblings.png`` — three siblings share one ``<pattern>``; the
  first is painted with ``fill-opacity="0.5"``. The second and third
  squares must be fully opaque blue: the opacity must not accumulate in
  the shared definition.
* ``pattern_bbox.png`` — two siblings share an ``objectBoundingBox``
  pattern; both halves must be identical (the first use must not consume
  the definition's ``width``/``height``).

Before/after the fix
--------------------

* ``pattern_bbox_before_fix.png`` — rendered with the pre-fix sources:
  the second sibling loses the pattern (transparent), because the first
  use popped ``width``/``height`` out of the shared definition.
* ``pattern_bbox_after_fix.png`` — same document after the fix: both
  halves identical.
